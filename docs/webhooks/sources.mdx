An endpoint's `source` defines how Trigger.dev verifies requests and types the event every subscriber receives. Choose a [built-in provider source](/webhooks/providers), such as `webhooks.stripe()` or `webhooks.firecrawl()`, or supply a verification configuration with [`webhooks.custom()`](/webhooks/custom-providers).

## Presets

Presets supply the verification configuration, and most also carry the provider's part of the endpoint's [setup prompt](/webhooks/connect#set-it-up-with-an-ai-agent). Set the endpoint's signing secret or public key as described in [Connect a provider](/webhooks/connect).

<CodeGroup>

```ts /trigger/stripe.ts
import { webhook, webhooks } from "@trigger.dev/sdk";

export const stripe = webhooks.endpoint.define({ id: "stripe", source: webhooks.stripe() });

export const stripeEvents = webhook({
  id: "stripe-events",
  endpoint: stripe,
  onEvent: async ({ event }) => {
    if (event.type === "payment_intent.succeeded") {
      console.log(event.id);
    }
  },
});
```

```ts /trigger/github.ts
import { webhook, webhooks } from "@trigger.dev/sdk";

export const github = webhooks.endpoint.define({ id: "github", source: webhooks.github() });

export const githubEvents = webhook({
  id: "github-events",
  endpoint: github,
  onEvent: async ({ headers }) => {
    // GitHub puts the event type in a header
    console.log(headers.get("x-github-event"));
  },
});
```

```ts /trigger/svix.ts
import { webhook, webhooks } from "@trigger.dev/sdk";

export const svix = webhooks.endpoint.define({ id: "svix", source: webhooks.svix() });

export const svixEvents = webhook({

  },

```

```ts /trigger/composio.ts

  id: "composio-events",
  endpoint: composio,
  onEvent: async ({ event }) => {
    console.log(event);
  },
});
```

</CodeGroup>

The available presets are `stripe()`, `github()`, `svix()`, `standardWebhooks()`, `square()`, and `discord()`. More than 40 named providers build on the same verifiers; see [Providers](/webhooks/providers) for the full list and each provider's setup.

### Svix and Standard Webhooks

`svix()` and `standardWebhooks()` use HMAC-SHA256 over `id.timestamp.body` with a base64-encoded `whsec_` secret. Their header names differ:

| Source | Headers |
| --- | --- |
| `svix()` | `svix-id`, `svix-timestamp`, `svix-signature` |
| `standardWebhooks()` | `webhook-id`, `webhook-timestamp`, `webhook-signature` |

Named sources such as `webhooks.clerk()` and `webhooks.composio()` select the corresponding configuration.

## Endpoint validation

Some sources also define a response for the provider's endpoint-validation request. These requests don't create deliveries or task runs.

`discord()` answers a verified `{ type: 0 }` PING with HTTP `204` and no body. It also returns `204` for accepted events and `401` for invalid signatures. Set the Discord application's public key as the endpoint's verification credential.

Slack's `url_verification` challenge is handled the same way by `@trigger.dev/slack`.

`whatsapp()` answers Meta's GET verification request when `hub.mode` is `subscribe` and `hub.verify_token` matches the endpoint's verify token. It returns `hub.challenge` as text. The verify token is separate from the App Secret used to verify event signatures; see [Verify a WhatsApp endpoint URL](/webhooks/connect#verify-a-whatsapp-endpoint-url). Endpoints without GET verification return `405` to GET requests.

## Typing the event

Stripe and GitHub sources provide default event shapes; other sources default to `unknown`. Pass an event type to the source function for typed handler parameters and autocomplete. This example uses `Stripe.Event` from the `stripe` package, which must be installed in your project:

```ts /trigger/stripe.ts
import type Stripe from "stripe";
import { webhook, webhooks } from "@trigger.dev/sdk";

export const stripe = webhooks.endpoint.define({ id: "stripe", source: webhooks.stripe<Stripe.Event>() });

export const stripeEvents = webhook({
  id: "stripe-events",
  endpoint: stripe,
  onEvent: async ({ event }) => {
    console.log(event.type, event.id);
  },
});
```

For `webhooks.custom<T>()`, pass your own event type as `T`. The endpoint's event type flows to every subscriber: `webhook()` handlers, `chat.event` keys and filters, and [waiter](/webhooks/waiters) `match` paths are all checked against it.

<Note>
  Event types are compile-time annotations. Signature verification doesn't validate the body against
  a TypeScript type. Validate `event` inside `onEvent` if your handler needs runtime schema checks.
</Note>

## How verification works

Requests must pass verification before they reach any subscriber. Sources can check a signature or credential, enforce a timestamp tolerance, and derive an idempotency key for [deduplication](/webhooks/deliveries#deduplication). Verification failures return the source's rejected HTTP status (`400` by default).

To verify a provider without a built-in source, choose a scheme in a [custom source](/webhooks/custom-providers#verification-schemes).

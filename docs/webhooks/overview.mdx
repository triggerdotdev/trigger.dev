**A webhook endpoint is one hosted URL that you register with a provider.** Trigger.dev [verifies](/webhooks/verification) every request from the provider, records it as a [delivery](/webhooks/deliveries), and hands the event to everything subscribed to the endpoint.

Webhooks can start, resume or message your AI agents.

<Note>
  Webhooks are in public beta for every organization, in `@trigger.dev/sdk` 4.8.1 and later. The API
  may change before general availability; we announce changes in the
  [changelog](https://trigger.dev/changelog). Send bugs and feedback to
  [eric@trigger.dev](mailto:eric@trigger.dev) with the delivery id (`whd_...`) or run id.
</Note>

[Built-in providers](/webhooks/providers) include Stripe, GitHub, Firecrawl, Linear and more than 40 others. For any other provider, define a [custom provider](/webhooks/custom-providers). If you prefer to handle webhooks in your own app, you can [trigger tasks from your own handler](/webhooks/own-handler). To set one up from scratch, follow the [quick start](/webhooks/quick-start).

Declare the endpoint once, then subscribe to it:

```ts /trigger/stripe.ts
import { webhook, webhooks } from "@trigger.dev/sdk";

export const stripe = webhooks.endpoint.define({
  id: "stripe",
  source: webhooks.stripe(),
});

export const fulfillOrder = webhook({
  id: "fulfill-order",
  endpoint: stripe,
  filter: "event.type == 'checkout.session.completed'",
  onEvent: async ({ event }) => {
    console.log("Fulfilling", event.data.object.id);
  },
});

export const recordRefund = webhook({
  id: "record-refund",
  endpoint: stripe,
  filter: "event.type == 'charge.refunded'",
  onEvent: async ({ event, headers, endpoint, ctx }) => {
    console.log("Refund", event.id, "on", endpoint?.id, "in run", ctx.run.id);
  },
});
```

Stripe gets one URL. A checkout event runs `fulfill-order`, a refund runs `record-refund`, and anything else is recorded as `FILTERED`.

## What can subscribe

| Subscriber | Declared with | What a delivery does |
| --- | --- | --- |
| Task | `webhook({ endpoint, onEvent })` | Starts a run of the task with the event. |
| Agent session | [`chat.event({ endpoint, key })`](/webhooks/session-routing) listed on a `chat.agent` | Delivers an action to the session the `key` names. |
| Chat frontend | a [channel connector](/webhooks/channels) such as `chat.channels.custom({ endpoint })` | Runs a turn on the conversation's session and posts the reply back. |
| Waiting run | [`webhooks.waiter.create(endpoint, { match })`](/webhooks/waiters) | Resumes a run that is waiting for this event. |

Each subscriber has its own [filter](/webhooks/filters), so one delivery can reach several subscribers and skip the rest. An endpoint can have up to 25 subscribers. An endpoint with no subscribers still gets a URL, so you can register it with the provider before writing the handlers.

## The handler

`onEvent` receives:

| Argument | Value |
| --- | --- |
| `event` | The verified request body, parsed as JSON. Its TypeScript type comes from the [source](/webhooks/verification#typing-the-event). |
| `headers` | Request headers as a Web `Headers` object, with case-insensitive `get()` and `has()` methods. Credentials such as signatures are removed. |
| `endpoint` | The endpoint the delivery arrived on: `id`, `declaredId`, `tenantId`, `externalRef`, and the `metadata` you declared. |
| `ctx` | The same [run context](/context) that regular tasks receive. |

`webhook()` also takes the options a [task](/tasks/overview) does, such as `queue`, `concurrency`, `machine`, `retry`, `maxDuration` and the lifecycle hooks. For example, to handle one delivery at a time:

```ts
export const orders = webhook({
  id: "stripe-orders",
  endpoint: stripe,
  queue: { concurrencyLimit: 1 },
  retry: { maxAttempts: 5 },
  onEvent: async ({ event }) => {
    // ...
  },
});
```

The limit covers every delivery the task handles. To process each customer's events in order while different customers run in parallel, route them to an agent with [session routing](/webhooks/session-routing): deliveries with the same key land in one session and are handled one after another.

`webhooks.endpoint.define` also takes a `description` and `metadata`. The metadata is passed to every subscriber as `endpoint.metadata`. The endpoint `id` can't start with `wh_`, which is reserved for the ids Trigger.dev generates.

Learn how to run a task for every completed Stripe checkout without writing a webhook handler. You'll declare a Stripe endpoint, subscribe a task to `checkout.session.completed`, register the endpoint's URL with Stripe, and send a test event.

Trigger.dev hosts the endpoint, verifies each request with your Stripe signing secret, deduplicates Stripe's retries on the event id, and runs the task with the verified event.

## Prerequisites

- A project set up with Trigger.dev and `@trigger.dev/sdk` 4.8.1 or later. See [Webhooks public beta](/webhooks/public-beta#install-the-packages).
- A [Stripe](https://stripe.com) account.
- The [Stripe CLI](https://docs.stripe.com/stripe-cli), for sending a test event. On some accounts an administrator has to turn on CLI access before `stripe login` works.
- The `stripe` package, for the event types:

<CodeGroup>

```bash npm
npm i stripe
```

```bash pnpm
pnpm add stripe
```

```bash bun
bun add stripe
```

</CodeGroup>

## Declare the endpoint and subscribe a task

Declare the endpoint with `webhooks.stripe()` and subscribe a task to it. The filter means only `checkout.session.completed` events start a run:

```ts /trigger/stripe.ts
import type Stripe from "stripe";
import { webhook, webhooks } from "@trigger.dev/sdk";

export const stripe = webhooks.endpoint.define({
  id: "stripe",
  source: webhooks.stripe<Stripe.Event>(),
});

export const fulfillOrder = webhook({
  id: "fulfill-order",
  endpoint: stripe,
  filter: "event.type == 'checkout.session.completed'",
  onEvent: async ({ event }) => {
    const session = event.data.object; // typed as Stripe.Checkout.Session by the filter
    console.log("Checkout completed", session.id, session.amount_total);
    // Fulfill the order here
  },
});
```

`webhook()` takes the same options as a [task](/tasks/overview), such as `retry`, `queue` and `machine`. To handle another Stripe event, subscribe another `webhook()` task to the same endpoint with its own [filter](/webhooks/filters).

## Register the endpoint with Stripe

<Steps>
  <Step title="Sync the endpoint">
    Run `trigger dev`, or deploy. Open the **Webhooks** page in your Development environment and select the `stripe` endpoint. Each environment has its own endpoint URL, and each team member has their own development environment. Register your development URL in a Stripe sandbox (or test mode) and the production URL in live mode.
  </Step>
  <Step title="Add the URL in Stripe">
    Copy the endpoint's **Webhook URL**. In the Stripe Dashboard, open the **Webhooks** tab in Workbench and choose **Create an event destination**:

    1. Select **Your account**.
    2. Choose the **Snapshot** payload, and the API version that matches your `stripe` package.
    3. Select the `checkout.session.completed` event.
    4. Choose **Webhook endpoint** as the destination type.
    5. Paste the URL as the **Endpoint URL**.

    <Warning>
      Stripe marks **Thin** as recommended, but thin payloads don't include `data.object`. Choose
      **Snapshot** so the task receives the full checkout session.
    </Warning>
  </Step>
  <Step title="Store the signing secret">
    On the destination's page in Stripe, choose **Reveal secret** and copy the signing secret (it starts with `whsec_`). Then choose **Set signing secret** on the Trigger.dev endpoint and paste it. Every delivery is rejected until the secret is set.

    To store it from the command line without printing it, put the secret in `STRIPE_WEBHOOK_SECRET` in your shell or `.env` file, then run:

    <CodeGroup>

    ```bash npm
    npx trigger.dev@latest webhooks set-secret stripe --env dev --from-env STRIPE_WEBHOOK_SECRET
    ```

    ```bash pnpm
    pnpm dlx trigger.dev@latest webhooks set-secret stripe --env dev --from-env STRIPE_WEBHOOK_SECRET
    ```

    ```bash bun
    bunx trigger.dev@latest webhooks set-secret stripe --env dev --from-env STRIPE_WEBHOOK_SECRET
    ```

    </CodeGroup>

    For production, repeat this step with the live-mode secret and `--env prod`.
  </Step>
</Steps>

To have an AI coding agent register the URL and secret instead, copy the endpoint's setup prompt. The agent creates its own Stripe endpoint with the Stripe CLI or API, so use either the prompt or the steps above, not both. See [Connect a provider](/webhooks/connect#set-it-up-with-an-ai-agent).

## Test it

With `trigger dev` running, send a test event with the [Stripe CLI](https://docs.stripe.com/stripe-cli). Run `stripe login` first, and make sure the CLI is on the same account and sandbox where you created the destination (`stripe login list` shows them):

```bash
stripe trigger checkout.session.completed
```

The event appears on the endpoint's **Deliveries** tab as **Succeeded**. Open the delivery to see the `fulfill-order` run it started. The Stripe CLI also creates events such as `payment_intent.created`, but Stripe only sends the events your destination subscribes to. If you subscribed to more events than the task's filter takes, those deliveries show as **Filtered** and start no run.

If no delivery appears, open the destination's **Event deliveries** tab in Stripe Workbench to see the HTTP status Trigger.dev returned, and check that Stripe uses the copied URL and that the signing secret matches. See [Deliveries and endpoints](/webhooks/deliveries) for every status and how to replay a delivery.
